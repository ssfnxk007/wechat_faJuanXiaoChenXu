## 后台 UI V3 收口（紧凑 ERP 风 · 主细表）—— Lead 页落地

### 背景
后台 17 个页面共用同一套 V2 视觉（`.business-page.page-v2` → 大圆角 24px、卡内 padding 22px、输入框 44px、4 列查询、每个 filter 都被 `.field-card` 再包一层，加上顶部 hero panel + 4 块 stat-card）。用户反馈「过于大了、有些没有规范」，给出了典型 ERP 后台截图：6 列查询条紧贴一行、表格行高小、状态字段为浅色色块、操作列单条「编辑」、无 hero、无大数据卡。

本轮目标：**1 个 lead 页（订单管理）+ 全局基线下沉**，其余 16 个页面下一轮按同一规范迁移。

### 决策（与用户对齐）
- 改造范围：1 个 lead 页 + 全局基线下沉；其余下一轮迁移
- UI 库：**继续纯手写**，不引入 Element Plus / Ant Design Vue
- Hero / Stats：**全部删除**，统一只保留 `search-card` + `data-card`
- 主细表对话框：**先优化现有详情弹窗 + 抽轻量外壳** `MainDetailDialog.vue`
- 列设置持久化：本轮不做，按钮位预留，点击为占位 toast

### 实施

|---|---|
| `frontend/src/style.css` | 末尾追加 V3 baseline 区段（约 360 行）。所有规则均用 `.admin-page` 后代选择器隔离，旧 16 个页面零影响 |
| `frontend/src/components/MainDetailDialog.vue` | 新建（38 行）。仅 title/sub/size/footer slot，size 支持 sm/md/lg/xl |

- **不动 `RemoteSelectField.vue`**：原计划同步控件高 44→32，但该组件被 6 个页面共用（订单 / 用户券 / 核销 / 券包 / 券包明细 / 轮播），改它会破坏 5 个未迁移页面。最终只在订单页使用，并保持其原 44px 高度（弹窗内表单本就比查询条更宽松，视觉协调）
